## 二、由此产生的硬性约束

1. **能交付**：完整、可读、结构正确的 SwiftUI / RealityKit 工程源码（`.xcodeproj` 或 `Package.swift` + 源码树）、资源清单、配置模板。
2. **不能交付**：编译产物、模拟器截图、真机 3D 帧率、StoreKit 沙箱支付回执、TestFlight 安装包。
3. 因此所有涉及上述内容的条目，在交付说明里必须写 **「未验证（缺 macOS + Xcode + 真机）」**，不允许写"应该能跑""已实现"。
4. 唯一能在本机真实验证的只有：**Web 样板**（`D:\work Buddy文档\2026-11-01-21-21-59\ai-edu-prototype`）的交互与视觉，可作为 iOS 还原的参照物，但**不等同于 iOS 验证**。

## 三、换到 macOS 后必须执行的验证清单

在装有 Xcode 16+ 的 Mac 上，逐条跑并把输出贴回 `01-开发清单.md` 对应步骤的"证据"栏：

```bash
# 1. 版本
xcodebuild -version
xcrun simctl list devices available | head -20

# 2. 依赖与编译
cd /path/to/App
xcodebuild -scheme FushiZhuan -destination 'platform=iOS Simulator,name=iPhone 16' build

# 3. 单元测试
xcodebuild test -scheme FushiZhuan -destination 'platform=iOS Simulator,name=iPhone 16'

# 4. 装到模拟器并截图（3D 页面必须走这条）
xcrun simctl boot "iPhone 16"
xcrun simctl install booted build/Build/Products/Debug-iphonesimulator/FushiZhuan.app
xcrun simctl launch booted com.yourorg.fushizhuan
xcrun simctl io booted screenshot ~/shot-3d.png

# 5. 真机（3D 帧率、语音、支付必须真机）
xcrun devicectl list devices
```

## 四、Web 样板的定位（重要）

当前已有 `ai-edu-prototype`（Web，Node 单端口 + 静态页面），它承担两个作用：

- **功能与视觉的参照物**：页面结构、文案、交互顺序、数据结构口径以它为准；
- **可立即演示的产物**：需要给人看效果时用它，别拿 iOS 源码当"能跑"的证据。

它 **不是** iOS 的替代品，也不能因为"网页已经能点"就宣称阶段完成。

## 五、技术选型前提（记录，后续变更要写进坑文档）

| 项 | 选择 | 理由 |
| --- | --- | --- |
| UI | SwiftUI（iOS 17+，`@Observable`） | 与样板单页状态驱动一致，迭代快 |
| 3D | RealityKit + `.usdz` 资产 | 技能强制 3D 不可推迟；RealityKit 是原生方案 |
| 本地存储 | SwiftData | 与 SwiftUI 结合好，单机够用；正式接后端时替换 Repository 层 |
| 语音 | `Speech`（识别）+ `AVSpeechSynthesizer`（合成） | 系统内置，无需三方；识别失败降级为文字输入 |
| AI 调用 | 自建代理（与 Web 样板同构）或 Keychain 存 Key 直连 | **决策点见 01 清单 S2.4**，不允许把 Key 写进源码/仓库 |
| 支付 | StoreKit 2 | 订阅 + 恢复购买必需 |
