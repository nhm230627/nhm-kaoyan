# 04 · 编译与验证（拿到 Mac 后照着做）

> 本机是 Windows 11，没有 `xcodebuild` / `swift` / `xcrun`，所以**所有代码目前都没有编译过**。
> 这份文档只做一件事：让你在 Mac 上第一次打开工程时，按顺序把错误清干净。
> 每清掉一条，回到 `02-问题与坑记录.md` 把对应的「验证」列补上。

## 二、第一次生成工程

```bash
cd /path/to/app
xcodegen generate
open FuShiZhuan.xcodeproj
```

应该没有任何报错。生成后目录里会多出 `FuShiZhuan.xcodeproj`（已被 `.gitignore` 排除，不需要提交）。

## 三、签名：先用免费 Apple ID，不要急着交 688

1. Xcode 菜单 → Settings → Accounts → 左下 `+` → 添加你的 Apple ID。
2. 选 `FuShiZhuan` target → Signing & Capabilities：
   - Team 选你的名字（Personal Team）
   - Bundle Identifier 如果冲突，把 `com.fushizhuan.app` 改成 `com.你的名字.fushizhuan`
3. 选一台模拟器（iPhone 16 即可），按 `⌘R`。

免费账号的限制：真机签名 **7 天过期**，过期后重新 `⌘R` 一次即可。模拟器不受限制。

## 五、第一轮编译最可能撞的 10 个错

按我写代码时的判断，这些是最可能出问题的地方。**遇到别的错请把完整报错贴给我，不要自己猜。**

| 报错关键词 | 大概原因 | 怎么改 |
| --- | --- | --- |
| `Cannot find 'AppState' in scope` | `AppState.swift` 没被收进 target | 检查 `project.yml` 的 `sources: FuShiZhuan` 是否覆盖整个目录；重新 `xcodegen generate` |
| `Missing argument for parameter 'from'` | `AppSnapshot` 手写了 `init(from:)` 但编译器找不到合成 init | 我给的是「手写解码 + 显式全参 init」，若报错把完整信息贴我 |
| `Type 'X' does not conform to 'Codable'` | 某个模型加了非 Codable 字段 | 贴报错，我在对应模型加 `CodingKeys` 或改字段类型 |
| `NSMicrophoneUsageDescription` 缺失 | Info.plist 没生成对（坑 P-16） | 打开 `FuShiZhuan/Resources/Info.plist` 看有没有这个 key；没有就检查 `project.yml` 的 `info.properties` |
| `Preview` 崩溃 | 预览没有注入 `AppState` | 预览代码里加 `.environment(AppState())` |
| `Cannot find 'FromToByAnimation' in scope` 或 `extra argument 'bindTarget'` | RealityKit 的动画 API 签名我按 iOS 17 写的，但没编译过 | 贴报错；退路是不用动画，只改 `entity.transform` 静态摆放，动画后补 |
| `Cannot find 'PerspectiveCamera' in scope` | 相机实体在部分 SDK 里叫法不同 | 换成给 `ARView` 设 `camera` 位置的写法，或直接用 `AnchorEntity(.camera)` |
| `Main actor-isolated ... in a synchronous nonisolated context` | `PurchaseService` 标了 `@MainActor`，`@StateObject` 初始化在非隔离上下文 | 把 `PurchaseService` 的 `@MainActor` 去掉，改成在 `Task { @MainActor in }` 里写状态 |
| `AVAudioApplication` 不可用 | 只在 iOS 17+ 有；工程部署目标是 17.0，理论可用 | 换回 `AVAudioSession.sharedInstance().requestRecordPermission` |
| `Static property 'productIDs' is not concurrency-safe`（若开了严格并发） | 工程里已经把 `SWIFT_STRICT_CONCURRENCY` 设为 `minimal` | 确认 `project.yml` 里那行还在 |

## 七、本机（Windows）现在能做的静态检查

不用等 Mac，现在就能查。`tools/check_code.py` 会做两件事：统计每行代码是否带尾部注释（覆盖率必须 100%）、检查 `{}` `()` `[]` 是否配平。

```bash
cd D:/APP
python tools/check_code.py
```

输出里每个文件一行，`OK` 表示这条规矩过了；出现 `NG` 会直接列出缺注释的行号。退出码非 0 就是有问题。

```bash
cd D:/APP
python tools/check_labels.py
```

第二个脚本查的是**结构体初始化的参数名与顺序**。Swift 要求实参顺序和声明一致，顺序写反在 Windows 上根本看不出来，一上 Mac 就是一片红。它把每个 struct 的声明顺序抽出来，再逐个比对调用点，`0 处` 才算过（P-23 就是这么发现的）。

> 这个脚本不是"编译"，它只能拦住格式与结构层面的低级错误。**括号平衡不等于能编译**，类型错误、访问控制、API 签名错误它一个都查不出来。

## 七点五、内购要先配商品（5 分钟，Apple 不帮你猜）

代码里写死了三个商品 id，必须一字不差地在下面两个地方之一建出来，否则付费墙只会显示「暂时没有可购买的商品」：

| 商品 id | 类型 | 建议价格（自己定） |
| --- | --- | --- |
| `com.fushizhuan.app.monthly` | 自动续期订阅 | 18 元 / 月 |
| `com.fushizhuan.app.yearly` | 自动续期订阅（同一订阅组） | 128 元 / 年 |
| `com.fushizhuan.app.lifetime` | 非消耗型 | 298 元 |

**本地测试（不用上架、不用审核）**：

1. Xcode 菜单 File → New → File… → 搜 `StoreKit Configuration File` → 建一个空的。
2. 在生成的文件里点左下 `+`，选 `Add Auto-Renewable Subscription` / `Add Non-Consumable`，把上面三个 id 与价格填进去。
3. Edit Scheme → Run → Options → `StoreKit Configuration` 选这个文件。
4. 直接跑模拟器就能买，不扣真钱。

**真机沙箱**：App Store Connect → 我的 App → 功能 → App 内购买项目里建同样三个；再在手机上用沙箱账号登录（设置 → App Store → 沙箱账户）。

> 注意：商品审核状态是「准备提交」也能拉取，但**必须至少有一次提交过**这个 App，否则 `Product.products` 会返回空数组。
