# 05 · AI 接入方案（BFF 代理）

> 结论：**App 不直连 DeepSeek**。App → 自己的 BFF → DeepSeek。
> Key 只存在服务器，客户端永远拿不到。这是行业标准做法，也是 App Store 审核更稳的做法。

---

## 一、为什么不用直连

| 风险 | 直连（Key 打进 App） | BFF |
| --- | --- | --- |
| Key 泄露 | 运行时必在内存，越狱/调试器可提取，扒出即刷爆余额 | 客户端拿不到，无从提取 |
| 限流 | 做不了 | 按设备每日限次 |
| 换模型 / 改提示词 | 要发版 + 等审核 | 服务端改完即生效 |
| 内容过滤 | 做不了 | 可在服务端拦 |
| 上架 | Key 明文在包里，有被拒风险 | 无此问题 |

## 二、目录与启动

```
D:\APP\server\
├── index.mjs         BFF 服务（零依赖，Node 18+）
├── .env.example      环境变量模板
├── .key              真实密钥（已被 .gitignore 排除，不要提交）
└── start.bat         Windows 双击启动
```

**启动**：双击 `start.bat`，或命令行 `node index.mjs`。默认端口 **4318**。

**配 Key 两种方式**（二选一）：
1. 在同目录放一个 `.key` 文件，内容是一行 Key（当前已放好）
2. 设系统环境变量 `DEEPSEEK_API_KEY`

没配 Key 时服务照常启动，但 `/health` 返回 `keyConfigured: false`，所有 AI 接口返回 503。

## 三、接口

所有接口统一：`content-type: application/json`，必须带两个头：

| 头 | 值 | 说明 |
| --- | --- | --- |
| `X-Device-Id` | 设备唯一标识 | 用于限流，App 首次启动生成并存 Keychain |
| `X-Service-Token` | 与环境变量 `SERVICE_TOKEN` 一致 | 最低门槛，正式版换成按用户签发的短令牌 |

### 3.1 健康检查

`GET /health` — 不鉴权，App 启动时探测服务是否在线。

```json
{ "ok": true, "service": "fushizhuan-bff", "model": "deepseek-chat",
  "keyConfigured": true, "dailyLimit": 60 }
```

### 3.2 出题 / 追问

`POST /v1/interview/turn`

请求：
```json
{ "sessionId": "s1", "turnIndex": 1, "phase": "major", "speaker": "majorA",
  "mode": "professional", "style": "standard", "history": [] }
```

`phase` 取值：`opening` / `foreign` / `major` / `comprehensive` / `closing`
`speaker` 取值：`lead` / `majorA` / `majorB` / `foreign` / `comprehensive`

响应：
```json
{ "requestId": "…", "question": "请你说说税收的公平原则和效率原则…",
  "knowledgePoints": ["税收公平原则","税收效率原则","公平与效率的权衡"] }
```

### 3.3 单轮评分

`POST /v1/interview/evaluate`

请求：`{ sessionId, turnIndex, speaker, question, answer }`

响应：
```json
{ "requestId": "…",
  "evaluation": {
    "completeness": { "score": 45, "evidence": "我觉得税收公平就是…", "comment": "…" },
    "logic": { "score": 50, "evidence": "…", "comment": "…" },
    "professionalExpression": { … }, "languageOrganization": { … },
    "manner": { "score": 0, "evidence": "", "comment": "" }
  },
  "improvements": [ { "issue": "…", "example": "…", "rewrite": "…" } ],
  "confidence": "medium",
  "uncertainty": "以下维度缺少原文依据，已作废：manner" }
```

**关键规则（服务端强制，不靠模型自觉）**：
- 每个维度的 `evidence` 必须是 `answer` 里真实出现的片段。服务端做去空白子串比对，**对不上就把该维度作废**（`score: 0, evidence: ""`），并写进 `uncertainty`。
- 有维度被作废时，`confidence` 自动从 `high` 降为 `medium`。
- `evidence` 为空的维度，App 显示「本维度依据不足」，**不显示 0 分**，避免误导。

### 3.4 整场总结

`POST /v1/interview/summary`

请求：`{ sessionId, mode, turns: [...] }`

响应：
```json
{ "requestId": "…", "headline": "一句话结论",
  "perQuestion": [ { "question": "…", "yourPoints": [], "missingPoints": [], "followUpExposed": "…" } ],
  "topActions": [ { "action": "…", "why": "…", "howToCheck": "…" } ],
  "confidence": "high", "uncertainty": [],
  "disclaimer": "训练量表，非院校官方评分；不预测录取结果" }
```

**幂等**：同一 `sessionId + turnIndex + 接口` 在 10 分钟内重复请求，直接返回首次结果（带 `"cached": true`），**不重复扣额度**。

## 四、错误码 ↔ iOS 的 AppError

| HTTP | code | 对应 iOS | 用户看到 | 恢复动作 |
| --- | --- | --- | --- | --- |
| 401 | `unauthorized` | `.unauthorized` | 令牌无效 | 重新登录后重试 |
| 401 | `missing_device` | `.unauthorized` | 缺少设备标识 | 重启 App |
| 429 | `quotaExceeded` | `.quotaExceeded` | 今日次数已用完 | 明天再来 / 开会员 |
| 503 | `aiUnavailable` | `.aiUnavailable` | 服务端未配置模型密钥 | 联系维护者 |
| 502 | `aiUnavailable` | `.aiUnavailable` | AI 服务异常 | 点重试 |
| 504 | `timeout` | `.timeout` | 请求超时 | 点重试或改文字作答 |

`retriable: true` 的才显示「重试」按钮；`quotaExceeded` 不给重试按钮，因为重试也没用。

## 六、上线前要改的三件事

| # | 现在 | 上线要换成 | 为什么 |
| --- | --- | --- | --- |
| 1 | `SERVICE_TOKEN` 一个固定串 | 按用户签发的短期令牌（登录后下发，24h 过期） | 固定串一旦泄露等于全开 |
| 2 | 限流存内存 Map | Redis / 云数据库 | 服务重启计数清零，多实例不共享 |
| 3 | 本机 `node index.mjs` | 云函数（腾讯云 SCF / Cloudflare Workers）+ 域名 + HTTPS | 手机上不能连 `127.0.0.1`，且必须 HTTPS |

**iOS 端会遇到的第一个问题**：模拟器可以用 `http://127.0.0.1:4318`，真机不行——真机必须用局域网 IP（如 `http://192.168.1.x:4318`）或公网 HTTPS 地址，且 iOS 默认禁止明文 HTTP，需要在 Info.plist 里为调试域名开 `NSAppTransportSecurity` 例外。正式版必须走 HTTPS。

## 七、iOS 侧怎么接（阶段 4 实现）

```
Services/
├── InterviewService.swift        协议：turn / evaluate / summary
├── RemoteInterviewService.swift  真实实现，URLSession 调 BFF
└── MockInterviewService.swift    假实现，返回固定数据，UI 开发期用
```

铁律：**协议先定，Mock 与真实实现共用同一协议与同一异常语义**。
Mock 返回的 `Improvement` / `DimensionScore` 结构必须与真实接口完全一致，否则切真实接口时 UI 会崩。

## 八、断网降级：客户端自己兜底（2026-11-02 新增）

> 起因：BFF 一停，整场面试就卡在「评分中」——既有 P-22 的收尾 bug，也因为没有任何本地兜底。
> 现在补齐了三条降级路径，**原则是：能继续就继续，但必须让用户看出这不是模型给的**。

| 挂在哪 | 降级到 | 用户看到 | 不兜的情况 |
| --- | --- | --- | --- |
| `nextQuestion` 失败 | `OfflineQuestions`（本地固定题库，按环节取） | 问题正常出，「离线粗评」标签 | `.quotaExceeded` / `.unauthorized` |
| `evaluate` 失败 | `LocalEvaluator`（字数、句数、结构词、专业词、英文词数） | 五维分数 + 「离线粗评」标签 + 复核提示 | 同上 |
| `summarize` 失败 | `LocalEvaluator.summarize`（最近一题均分 + 最弱一维） | 结论前缀「离线粗评：」 | 同上 |

三条铁律：

1. **只兜服务侧问题**。额度用完、未登录必须原样报给用户，不能用假分数盖住——那是把"没额度"伪装成"考完了"。
2. **离线分只做相对参考**。`manner`（综合素养）在离线状态下永远判为「依据不足」，因为机器确实看不出态度，不许编。
3. **标签一路带到存档**。`InterviewSession.isOffline` 靠 `uncertainty` 里 `离线粗评` 前缀识别，复盘页、结果页都会显示，不给存档加字段（避免老数据解码失败）。

对应代码：`Services/LocalEvaluator.swift`、`Services/OfflineQuestions.swift`、`InterviewEngine.fallbackQuestion` / `fallbackEvaluate` / `applyLocalSummary`。
