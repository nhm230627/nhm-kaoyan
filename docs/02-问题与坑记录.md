# 02 · 问题与坑记录（踩过的坑 + 怎么解决的）

> 用途：开发过程中所有"卡住过"的问题都记在这里，避免同一坑踩第二次。
> 规则：**只记真实发生过的**，写清现象→根因→解决→验证方式。没定位到根因的，就写"未定位"。
> 已有条目来自 Web 样板阶段（技术栈不同，但同类问题在 iOS 大概率复现，所以保留）。

---

## P-01 硕士帽流苏完全看不见

- **日期**：2026-11-02　**环境**：Web 样板 / Three.js
- **现象**：给宠物加流苏后，画面上什么都看不到。
- **定位过程**：先怀疑坐标，把流苏放到明显位置仍看不到；再查材质颜色——流苏是金色 `#ffd166`，宠物身体本身是黄色。
- **根因**：① 颜色和身体几乎同色；② 线段半径只有 0.014，在 200px 画布里不到 1px；③ 位置落在帽板内部，被帽板实体遮住。
- **解决**：改暗红 `#ef3b30` + 金环 `#ffc93c`；半径加到 0.042→0.046；整组 `scale 1.25`；横段抬到帽板上方 `y=0.05`。
- **验证**：截图逐版对比（`n-pet.png` → `n-pet2.png` → `n-pet3.png`），最终小尺寸下也能一眼看到。
- **教训**：**做 3D 装饰件，先检查"是否被别的实体包住"，再谈颜色和粗细。**

## P-02 流苏垂段被头球吃掉

- **日期**：2026-11-02　**环境**：同上
- **现象**：横段能看见，往下垂的那截不见了。
- **根因**：垂段放在 `x=0.335, z=0.115`，而**帽板是边长 0.66、绕 Y 轴旋转 45° 的方块**，斜角半径 = 0.33×√2 ≈ 0.47，`x<0.47` 的部分都在帽板投影里；头球半径更大，还会盖住 z 较小的部分。
- **解决**：垂段挪到 `x=0.48, z=0.34`（既出帽板斜角，又在前方），穗子同理。
- **教训**：旋转过的方体，**包围半径要按对角线算**，不能按边长。

## P-03 拨穗动画"穗子横着指出去"

- **日期**：2026-11-02　**环境**：Web / SVG
- **现象**：整组流苏绕帽顶转 92° 后，流苏到了左边，但穗子是水平朝左的，像根棍子。
- **根因**：旋转的是整个 group，穗子跟着转了 92°，自然从"下垂"变成"平指"。
- **解决**：穗子单独包一层 `<g class="rt-fringe">`，父级转 +92°、子级反向转 -92°（同轴向抵消），穗子位移到左侧但保持下垂。
- **教训**：**要"整体移动但局部保持朝向"，就用父子反向旋转**，别去改坐标硬凑。

## P-04 截图里动画永远停在第一帧，误判"动画没生效"

- **日期**：2026-11-02　**环境**：Edge headless
- **现象**：给元素加了 transition，用 `--virtual-time-budget` 截图，出来还是起始态；一度以为 CSS 写错。
- **根因**：`--virtual-time-budget` 加速的是定时器，**CSS transition/animation 走的是渲染时钟，在这个模式下不推进**。
- **解决**：验收动画终态时，临时把目标 transform 写成元素默认值再截一张，确认终态正确后改回；运行时用真实浏览器人工确认。
- **教训**：无头截图只能验"静态终态/布局"，**不能验动画过程**。

## P-05 移动端布局"右侧被裁"，其实是截图工具

- **日期**：2026-11-01　**环境**：Edge headless
- **现象**：430px 窗口截图，右边按钮全被切掉，看起来像横向溢出。
- **根因**：**Edge headless 最小视口 496px**，传 430 会被撑到 496 再裁切，是工具行为不是 CSS 问题。
- **解决**：统一用 500×1050 截图；真要验 390pt 布局，用真机或 Safari 响应式模式。
- **教训**：**先怀疑工具，再怀疑代码**；固定一套可复现的截图参数并写进流程。

## P-06 公网分享链接反复失效（同根因 3 次）

- **日期**：2026-11-01 ~ 11-02　**环境**：cloudflared 临时隧道 + 本地 Node
- **现象**：发给别人时打不开；本地 curl 也连不上。
- **定位**：三段式排查——`curl 127.0.0.1:4321`（本地服务）→ `tasklist | grep cloudflared`（隧道进程）→ `curl 公网域名`（链路）。三次都是本地服务与隧道**双双消失**。
- **根因**：两者都是 AI 会话里起的后台进程，**会话结束被系统回收**；trycloudflare 免费隧道也不保证存活，且**每次重启域名都变**。
- **解决**：① 短期：每次重新起，提供新链接；② 长期：写 `share.bat`/`share.ps1` 让用户在自己桌面会话里起（进程不随 AI 会话死）；③ 根本方案：发布成固定在线链接（不依赖任何人的电脑开机）。
- **教训**：**"能打开"和"能长期打开"是两件事**，给非技术用户发链接前先说清有效期。

## P-07 面试总结把英文答案算成 1 个词

- **日期**：2026-11-02　**环境**：Web / JS
- **现象**：英语环节说了 53 个词，点评写"只说了 1 个词"。
- **根因**：统计用的是 `clean(text).split(/\s+/)`，而 `clean` 先删掉了所有空白，英文被压成一个 token。
- **解决**：单独写 `wordCount()`：先把非 ASCII 字符替换成空格，再按 `[A-Za-z]` 计 token。
- **教训**：**中文文本处理里的"去空格"不能复用到英文计数**。

## P-08 点评模板重复（三题都是"建议加上第一、第二"）

- **日期**：2026-11-02　**环境**：Web / JS
- **现象**：五维总结里三条建议一模一样。
- **根因**：所有题目落到同一个兜底分支，兜底文案是常量。
- **解决**：改成按阶段配置"要点命中表"（踩到了哪些关键词、还差哪些），并加"是否已自带结构词"判断；兜底句按题目序号轮转。
- **教训**：**兜底文案必须是数据驱动的**，否则一眼假。

## P-09 关卡 id 解析错，点关卡没反应

- **日期**：2026-11-02　**环境**：Web / JS
- **现象**：点第一关没进战斗，控制台无报错。
- **根因**：关卡 id 是 `tax-system-1`，代码按 `split('-')` 取章节得到 `"tax"`，`CHAPTERS.find` 找不到就 `return` 了——**静默失败**。
- **解决**：改成 `id.replace(/-\d+$/,'')` 取章节，序号取末段；找不到章节时明确抛错/提示，不再静默返回。
- **教训**：**函数不要静默 return**，尤其是用户点了按钮的入口。

## P-10 题库异步加载，进关卡时"空跑"

- **日期**：2026-11-02　**环境**：Web / JS
- **现象**：从别处跳进闯关，战斗层不出现；过一会儿再点就正常。
- **根因**：题库是 `fetch` 异步拉取，`startLevel` 在数据到达前执行，`bank` 为空直接 return。
- **解决**：加 `tries` 重试（20 次 × 120ms），超时才提示"题库还没加载好"。
- **教训**：**所有"依赖异步数据才能打开"的入口，都要重试或禁用态**，不能靠 setTimeout 猜时间。

## P-11 广场里宠物名字互相压、宠物堆成一坨

- **日期**：2026-11-02　**环境**：Web / Canvas 2D
- **现象**：13 只宠物名字叠在一起看不清；一半挤在中间。
- **根因**：随机散布 + 没有碰撞，绘制顺序只按 y 排，标签无避让。
- **解决**：① 出生位置用**抖动网格**铺开；② 每帧加两两**分离力**（距离 < 34 推开）；③ 水池用椭圆公式往外推；④ 标签做**矩形碰撞检测**，冲突就上移最多 2 档。
- **教训**：多实体场景，**分布、避让、层级**是三件独立的事，要分别处理。

## P-12 口粮"首通 +2"永远变成 +1

- **日期**：2026-11-02　**环境**：Web / JS
- **现象**：第一次通关也只加 1 份口粮。
- **根因**：`firstClear` 的判断写在 `store.patch()` **之后**，此时该关已被写进 `cleared`，判断永远为 false。
- **解决**：把 `firstClear` 提到 patch 之前计算。
- **教训**：**"是否首次"这类判断必须在写入前取**，顺序错了逻辑就反。

## P-13 API Key 配置了但前端仍提示"未配置"

- **日期**：2026-11-02　**环境**：Web / Node
- **现象**：服务端已内置 Key，浏览器仍弹"去填 Key"，AI 按钮不发请求。
- **根因**：前端 `hasKey()` 只看 localStorage，不看服务端是否有 Key；`chatOnce` 也没发请求就抛 `NO_KEY`。
- **解决**：启动时 `detectServerKey()` 探测 `/api/health`（2.5s 超时），`hasKey()` 改成"本地有 或 服务端有"；去掉客户端的前置抛错，空 Key 交给服务端补。
- **教训**：**"能力在不在"要问真正的持有方**，不能拿本地缓存当唯一事实。

## P-14 首通奖励又写成"永远重复通关" —— 同一个坑第二次踩

- **日期**：2026-11-02　**环境**：iOS / SwiftUI（未编译验证）
- **现象**：`LevelPlayView` 结果页显示"口粮 +1"，即使这一关从没打过。
- **根因**：和 Web 版 P-12 完全同因——写成 `app.levelResult(for: levelID) == nil ? 2 : 1`，但这一行求值时 `finishLevel` 已经把成绩写进 `levelResults`，永远返回 1。
- **解决**：在 `finishLevel` **之前**取 `let isFirstClear = app.levelResult(for: levelID) == nil`，把 2/1 存进 `@State foodGained`，结果页只读这个值。
- **教训**：**同一个逻辑在换技术栈后会原样复现**。P-12 当时只修了 Web，没把规则写进设计约束，所以 Swift 版照抄了错误写法。此后凡"首次/是否已存在"的判断，一律在写入前取快照，且这条已写进 `AppState.finishLevel` 的注释。
- **验证**：⚠️ 未编译。逻辑层面已复核：`firstClear` 在 `data = snap` 之前计算。

## P-15 占位式"保护调用"是伪装完成度

- **日期**：2026-11-02　**环境**：iOS / Swift
- **现象**：`submit()` 里第一版写了 `app.resolveWrong(questionID: "")`，注释是"占位保护：不存在的 id 不会改动任何数据"。
- **根因**：为了让分支看起来"处理了错误"而写一行无效代码。它不会报错，所以永远不会被发现；但它也没做任何事，属于用代码掩盖没想清楚。
- **解决**：直接删掉该分支。错题入库本来就在 `AppState.recordAnswer` 内部完成，视图层不该二次写。
- **教训**：**"不报错的空操作"比报错更危险**。凡是写"占位/保护/兜底"的调用，要么它能真正改变行为，要么删掉。

## P-16 project.yml 里两套 Info.plist 打架

- **日期**：2026-11-02　**环境**：XcodeGen
- **现象**：初版 `project.yml` 同时写了 `GENERATE_INFOPLIST_FILE: YES` + 一堆 `INFOPLIST_KEY_*`，又写了 `info.path: .../Info.plist`。
- **根因**：这是两条互斥路径——前者让 Xcode 自动生成 plist，后者让 XcodeGen 写一份真实 plist 文件。同时开启时，自定义 key（如 `NSMicrophoneUsageDescription`）可能落在被忽略的那一份里，表现为"代码里声明了权限、运行时就是弹不出授权框"。
- **解决**：只保留一条：`GENERATE_INFOPLIST_FILE: NO` + `info.path` 显式 plist，所有权限文案写进 `info.properties`。
- **教训**：**配置项之间会互斥**。加配置前先确认它和现有项是不是同一件事的两种做法。
- **验证**：⚠️ 未在 Xcode 验证。要在 Mac 上跑一次 `xcodegen generate` 后检查生成的 `Info.plist` 是否含 `NSMicrophoneUsageDescription` 才能确认。

## P-17 不用手写 project.pbxproj

- **日期**：2026-11-02　**环境**：Windows（无 Xcode）
- **现象**：第一反应是手写 `project.pbxproj` 让用户双击就能打开，省掉装工具。
- **根因**：pbxproj 是结构化 plist 文本，UUID 交叉引用几百处，任何一处对不上就是"工程打不开"，而且在 Windows 上**无法验证**。交付一个没验证过、还可能直接打不开的工程文件，比不交付更糟。
- **解决**：改用 `project.yml`（XcodeGen）。Mac 上 `brew install xcodegen && xcodegen generate` 一条命令出工程；工程文件本身进 `.gitignore`，靠 YAML 复现。
- **教训**：**在无法验证的环境里，选可验证的路径**。文本描述 → 工具生成，比手写二进制结构可靠。

## P-18 「重试」按钮只清了错误，状态没回来 → 死路

- **日期**：2026-11-02　**环境**：iOS / Swift
- **现象**：出错后界面出现「重试本题」，点下去错误提示消失了，但提交按钮仍然是灰的，怎么点都没反应。
- **根因**：`clearError()` 只做了 `error = nil`。错误态是 `session.state == .error`，而 `canAnswer` 要求 `state == .asking`。清掉错误文案不等于把状态拉回来，于是界面看着正常、实际卡死。
- **解决**：新增 `InterviewEngine.retry()`——题已经出过就把状态拉回 `.asking` 并重启计时；题都没出来就重新 `askNext()`。按钮改调它。
- **教训**：**"显示层清掉了" ≠ "状态回来了"**。凡是错误恢复，必须回答"恢复到哪个状态"，否则就是给自己造死路。

## P-19 提交失败时把用户刚写好的回答清空了

- **日期**：2026-11-02　**环境**：iOS / Swift
- **现象**：网络一断，点了提交，报错了，作答框也空了——刚打的几百字没了。
- **根因**：`submit()` 里 `await engine.submit(text)` 之后无条件 `answer = ""`，把"提交成功"的清理动作当成了"提交结束"的清理动作。
- **解决**：改成 `if engine.error == nil { answer = "" }`，失败时原文留在框里，用户改完直接重提。
- **教训**：**清理动作要绑在成功分支上**。失败时最该保留的就是用户输入，那是他唯一不想重做的东西。

## P-20 Info.plist 里没声明的 key 会静默走代码默认值

- **日期**：2026-11-02　**环境**：XcodeGen / iOS
- **现象**：`AppConfig` 读 `BFFBaseURL`、`BFFServiceToken`、`UseMockService` 三个 key，但 `project.yml` 的 `info.properties` 里一个都没写。模拟器上一切正常（因为默认值正好是 `127.0.0.1:4318`），换到真机就永远连不上，且没有任何报错。
- **根因**：`object(forInfoDictionaryKey:)` 取不到就 `??` 兜底，兜底值刚好和开发机一致，把"配置缺失"伪装成了"配置正确"。真机上 `127.0.0.1` 指向手机自己，必然是连不上。
- **解决**：三个 key 全写进 `project.yml` 的 `info.properties`，并在文档里写明真机要换成局域网 IP、上线要换 HTTPS 域名。
- **教训**：**默认值和开发环境重合时，等于没有默认值检查**。凡是靠 plist 注入的配置，必须在文档里列清 key 名，缺一个就是真机上的一颗雷。

## P-21 中途放弃的场次被当成 0 分展示

- **日期**：2026-11-02　**环境**：iOS / Swift
- **现象**：点「结束」退出面试后，结果页照常显示「本场已结束」+ 量表说明，只是没有分数。用户看到的像是"考完了但没得分"，而不是"这场没考完"。
- **根因**：结果页只判断"是否终态"，没区分 `.abandoned` 和 `.feedback`。而 `abandoned` 的会话没有 `scores`，`ForEach` 渲染空，页面就只剩下一个空壳。
- **解决**：结果页和复盘页都加了 `.abandoned` 分支，明确写「本场未完成 / 不生成评分 / 这一次额度已用掉」，并隐藏评分卡。
- **教训**：**终态不等于完成态**。状态机里每个终态都要有自己的界面，否则就会用"完成"的皮去盖"没完成"的骨。

## P-22 用 isBusy 当收尾重入锁 → 最后一题永远出不了结果

- **日期**：2026-11-02　**环境**：iOS / Swift
- **现象**：答完第 9 题后，界面一直停在「评分中」，没有结果、没有错误、也不结束。整场面试等于白考。
- **根因**：`submit()` 一进来就把 `isBusy = true`，答完最后一轮时 `advance()` 内部调 `finish()`，而 `finish()` 第一行是 `guard !isBusy else { return }`——重入锁把自己锁在了门外。这一行是照着"防重入"的直觉写的，四个月都不会有人发现，因为只有走满全场才触发。
- **解决**：新增独立的 `isFinishing` 专门防收尾重入，`isBusy` 只管"按钮转圈"。同时在注释里写清为什么不能用 `isBusy`。
- **教训**：**重入锁必须锁自己那个操作**。拿"正在忙"当"正在收尾"用，等于把正常路径也判成重入。凡是用一个状态标记两件事，都要问一句：这两件事会不会同时发生。

## P-23 结构体参数顺序写反，编译期才报错

- **日期**：2026-11-02　**环境**：iOS / Swift（Windows 上无编译器）
- **现象**：模考大厅里写 `StatTile(title: "我的", value: "\(score)")`，而声明是 `StatTile(value:title:tint:)`。Swift 要求实参顺序与声明一致，这行必然编译失败。
- **根因**：靠记忆写调用，而声明在另一个文件里；Windows 上没有编译器，写完无从发现。
- **解决**：写 `tools/check_labels.py`——扫出所有 struct 的声明顺序（有显式 `init` 用 `init` 参数，否则用存储属性），再扫所有调用点，检查标签名存在且相对顺序一致。自测时故意写两行错的，脚本两条都抓到。
- **教训**：**没有编译器，就把编译器的某一条规则手写成脚本**。参数顺序、标签名这种机械规则最容易漏也最容易查，值得用工具兜住。

## P-24 文案里的阶段号抄错，页面已经有出口却还写着"阶段 X 接入"

- **日期**：2026-11-02　**环境**：iOS / SwiftUI

## P-25 @Published 属性不能在 super.init() 之前赋值

- **日期**：2026-11-02　**环境**：iOS / Swift
- **现象**：`MentorVoice` 是 `NSObject` 子类（因为要当 `AVSpeechSynthesizerDelegate`），第一版写成「先给 `isMuted` 赋值，再 `super.init()`」。
- **根因**：`@Published` 是属性包装器，背后是一个存储属性 `_isMuted`。在 `super.init()` 之前用包装器的 setter 赋值，等价于在 `self` 还没完全初始化时就调用它的方法，Swift 会报 `self used before super.init()`。
- **解决**：给 `@Published` 声明加默认值，改成「先 `super.init()`，再赋值」。同时把「为什么不用 @Observable」写进文件头注释：`NSObject + @Observable` 没把握编译通过，`NSObject + ObservableObject` 是十年验证过的组合。
- **教训**：**继承 NSObject 的类，初始化顺序比结构体严格得多**。属性包装器、`lazy`、`didSet` 这类东西都要求在 `super.init()` 之后才碰。

## P-27 `generateBox` 的参数叫 `depth`，不叫 `length`

- **日期**：2026-11-02　**环境**：GitHub Actions / macOS 26.6.2 + Xcode 26.6（**首次真实编译**）

## P-28 `generateCylinder` 是 iOS 18 才有的 API，最低版本设 17 编不过

- **日期**：2026-11-02　**环境**：GitHub Actions / Xcode 26.6
- **现象**：同一文件 4 处报 `'generateCylinder(height:radius:)' is only available in iOS 18.0 or newer`（地台、帽围、金环、流苏绳）。
- **根因**：RealityKit 在 iOS 18 才补上 `generateCylinder` / `generateCone`。iOS 17 及以前只有 box / sphere / plane / text。工程 `deploymentTarget` 写的是 17.0，所以全部够不着。
- **处理**：**把 `project.yml` 的 iOS 最低版本从 17.0 提到 18.0**，理由写进了 yml 注释。关键判断：iOS 18 与 iOS 17 支持的最低机型完全相同（iPhone XR / XS 及之后），抬到 18 实际只放弃「不愿升级系统的极少数用户」。
- **备选方案（未采用）**：① 用 `if #available(iOS 18, *)` 分支 + iOS 17 降级成方块近似——帽围会明显变方；② 保留 17，改用 `MeshDescriptor` 手搓圆柱——代码量翻倍且本机无法验证。
- **教训**：**版本号不是随手填的数字，它决定了哪些 API 能用**。以后每引一个系统 API，先想它在哪个版本才有。

## P-29 `catch { }` 的隐式 `error` 常量会遮蔽同名的类属性

- **日期**：2026-11-02　**环境**：GitHub Actions / Xcode 26.6
- **现象**：`SpeechService.swift` 第 40、58 行同时报两条 `error: cannot assign to value: 'error' is immutable` 和 `error: type 'any Error' has no member 'speechUnavailable'`。
- **根因**：Swift 的 `catch { }` 会把捕获到的错误隐式绑定成名为 `error` 的**常量**。只要不写 `catch let e`，这个常量就在整个 catch 块内遮蔽类的 `error` 属性。于是 `error = .speechUnavailable(...)` 变成「给常量赋值」，而 `.speechUnavailable` 会去 `any Error` 上找成员，当然找不到。
- **处理**：两处改成 `self.error = AppError.speechUnavailable(...)`——`self.` 强制指向属性，并写明枚举类型名让简写有落脚点。**不是把属性改名**，因为 `error` 这个名字对外调用方更直观。
- **教训**：**同名遮蔽是 Swift 里最难凭肉眼发现的一类错**。凡是在 `catch` 块里给 `error` 赋值，一律写 `self.`。

## P-30 语音权限的状态类型叫 `SFSpeechRecognizerAuthorizationStatus`

- **日期**：2026-11-02　**环境**：GitHub Actions / Xcode 26.6
- **现象**：`'AuthorizationStatus' is not a member type of class 'Speech.SFSpeechRecognizer'`，连带 `generic parameter 'T' could not be inferred`。
- **根因**：写成 `SFSpeechRecognizer.AuthorizationStatus`（当成嵌套类型）。实际它是 Speech 框架的**顶层枚举** `SFSpeechRecognizerAuthorizationStatus`。
- **处理**：改成顶层名。第二条「泛型推断失败」是第一条的**连带错误**——泛型参数类型写错后 `withCheckedContinuation` 推不出 `T`，修好类型名就一起消失。
- **教训**：**一条报错常常带一串连带错误，先修第一条**。另外 OC 风格的框架里，枚举大概率是顶层名字（前缀+类型），不是嵌套。

## P-31 Swift 分批编译导致「改一批暴露一批」，靠 CI 反复跑很浪费

- **日期**：2026-11-02　**环境**：GitHub Actions
- **现象**：第一次编译只报 `PetSceneView` 的 6 条错误；修完再跑，又冒出 `SpeechService` 的 6 条。看起来像「改不完」。
- **根因**：Debug 配置下 Xcode 按批次（batch）编译 Swift 文件，**前一批失败后，后面的文件根本没轮到编译**。所以第一轮看到的错误数远小于真实错误数。
- **处理**：在 workflow 的 `xcodebuild` 命令后加 `SWIFT_COMPILATION_MODE=wholemodule`，让整个模块一次性编译，所有文件的错误一轮全报。**只加在 CI 命令行上，不动工程配置**，避免影响以后在 Xcode 里本地增量编译的速度。
- **教训**：**在只能靠 CI 验证的环境里，「一轮报全」比「编译快」重要得多**。每多一轮 CI 就多消耗额度、多等 4 分钟。
