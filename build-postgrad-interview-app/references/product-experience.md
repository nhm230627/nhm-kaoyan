# 产品与体验规格

用于建体验地图（第 1 步）和阶段 7 验收。这里定义"有什么、在哪、怎么串、怎样算过"，不涉及实现细节。

## 1. 产品定位

面向考研复试（首个专业：税务专硕，架构支持扩展到其他经管类专业）的原生 iOS 备考 APP。
用户价值：把"复试准备"这件没有明确路径的事，变成每天有任务、有反馈、有陪伴的过程。

不做：求职撮合、机构抽成、分销、院校排名评价、录取概率预测。

## 2. 导航骨架

五个 Tab，顺序固定：

1. **学习**（首页 + 课程 + 资料 + 题库）
2. **面试**（AI 模拟面试入口 + 历史复盘）
3. **社区**（3D 社区大厅 + 伙伴）
4. **成长**（3D 形象 / 电子宠物 / 成就 / 成长明细）
5. **我的**（资料、会员、消息、设置）

栈内页面从 Tab 推入，返回路径唯一。3D 场景页以全屏方式进入，退出按钮固定在安全区左上角，不使用手势作为唯一返回方式。

### 3.3 题库训练

| 功能 | 必要状态 |
| --- | --- |
| 筛选 | 科目 × 知识点 × 题型 × 难度，可多选可清空 |
| 答题 | 未作答/已选未提交/已提交/超时 |
| 解析 | 有解析/解析加载中/无解析 |
| 收藏 | 已收藏/未收藏/同步失败 |
| 错题重练 | 全量/仅未掌握/按知识点 |
| 练习历史 | 有记录/无记录/分页加载 |
| 正确率与薄弱点 | 样本足够/样本不足提示 |

规则：
- 每道题必须带 `source`（来源）、`reviewStatus`（未审核/已审核/已下线）、`updatedAt`。未审核内容不得进入正式题库列表，只能出现在「AI 生成待审核」区且默认折叠。
- 面试题与专业课题库通过 `linkedQuestionIDs` 双向关联，任一方向可跳转。
- 薄弱知识点由正确率与最近出错时间共同决定，计算公式写在领域层并被单元测试覆盖。

### 3.4 AI 模拟面试

入口在面试 Tab。完整闭环见 `ai-interview.md`，此处只锁产品面：

- **面试间必须有真实场景**：会议室、长桌、5 位导师围坐（组长居中）、考生第一人称视角。不得用一个光球或一句文字提示代替导师席。5 人依据为教育部规定的"面试小组一般不少于 5 人"。
- **导师有分工**：组长（主问与控场）、专业导师 A（税收理论）、专业导师 B（实务与政策）、外语导师（英文环节）、综合导师（经历、规划、素养），另可设记录秘书。当前发言人高亮。
- **环节顺序**：全真模式下按"组长开场 → 外语 5 分钟 → 专业抽题与追问 → 综合提问 → 组长收尾"，总时长默认 20 分钟。
- 准备页：专业、题型、难度、时长、模式（专业面试 / 综合面试 / 学习经历追问）、导师风格（温和 / 标准 / 严格）、输入方式（文字 / 语音）。
- 过程页：当前题、追问、计时、暂停、跳过、结束、转写编辑、字幕开关、"生成阶段总结"。
- **总结**：结束后面试自动生成总结；过程中也可手动生成阶段小结。总结含整体五维、逐题复盘（你说到的要点 / 缺失要点 / 追问暴露的问题）、3 条可执行改进动作、改进示例、推荐练习。
- 反馈页：五维评分 + 引用片段 + 按导师归属的追问统计 + 改进示例 + 量表说明。
- 历史页：记录列表、单次详情、多次对比、重练。
- 免责：导师为 AI 模拟角色，不预测录取结果，不冒充院校官方评分，示例不是唯一答案。

### 3.6 3D 学习社区

产品面要求（技术面见 `3d-community.md`）：

- 三个场景：社区大厅、个人学习空间、好友/小组共同学习空间。
- 场景内可见：自己的形象、伙伴形象、电子宠物、学习设施、互动热点。
- 交互：相机旋转/缩放/平移/复位、点击角色与物体、动作表情、快捷鼓励。
- 社交：好友列表与状态（在线/学习中/休息中/离线）、打卡、共同学习、鼓励、提醒。
- 安全：举报、拉黑、内容审核态、隐私可见范围。
- 提醒必须由用户显式授权，且可随时关闭；关闭后不发送本地通知。

### 3.7 会员订阅

| 状态 | 表现 |
| --- | --- |
| 未订阅 | 权益对比表、价格、购买按钮 |
| 购买中 | 进度、可取消 |

### 3.8 消息与个人中心

- 消息类型：学习提醒、伙伴互动、系统公告。已读/未读、全部已读、免打扰。
- 个人中心汇总：课程进度、题库正确率、面试次数与趋势、成长等级、会员状态。
- 设置：通知、隐私、语音、个性化推荐、缓存清理、反馈、用户协议、隐私政策、注销账号。

### 3.9 刷题游戏化闯关

定位：把**知识点拆解**做成可通关的结构，不是给题库换皮。画面保持轻量（SwiftUI 2D + 简单动效即可），重投入放在"这道题考什么、为什么错、怎么记住"。

关卡结构：

```
科目 → 章节地图 → 关卡（每关 5–10 题，只考 1–2 个知识点）→ 3 星评价 → 解锁下一关
                                                                  ↓
                                                          错题汇集 → BOSS 关
```

玩法类型（按知识点性质选择，不做通用选择题换皮）：

| 玩法 | 适用知识点 | 交互 |
| --- | --- | --- |
| 概念配对 | 税种与特征、原则与定义 | 拖拽连线，错配即提示 |
| 流程排序 | 税收征管、行政复议、汇算清缴步骤 | 拖动排序，提交后逐项判定 |
| 计算闯关 | 增值税、企业所得税、个税计算 | 分步填空，每步给对错，不只看最终数 |
| 案例找错 | 涉税实务处理、筹划方案 | 在材料中标记错误点并选择正确处理 |
| 限时抢答 | 高频记忆点（税率、起征点、期限） | 倒计时 + 连击，答错不惩罚只记录 |
| BOSS 战 | 个人错题集合 | 连续答对 3 次同一题才算"击败" |

规则：
- **生命值可选**：默认 3 条命，答错扣 1，归零可重来；设置里可关闭生命值（无压力模式），关闭后不影响星级与成长。
- **星级判定**：3 星 = 全对且无提示；2 星 = 全对但用过提示；1 星 = 有错但通关；0 星不计星但记录完成。
- **解析强制**：每题答完必须展示"考的是哪个知识点 + 你为什么错 + 关联到哪一节"，不允许只显示正确答案。
- **与题库同源**：直接复用 `Question` 实体，新增 `gameMode` 与 `levelId` 字段，禁止另建一套题库。未审核内容不进关卡。
- **掌控度回写**：通关与 BOSS 击败结果写回 `mastery`，供薄弱点分析与首页任务使用。
- **成长值**：走 `GrowthService`，与普通刷题同一事件类型，不额外开一套计算，避免两处数值不一致。
- **防刷**：每日体力或次数有上限；重复刷已满星关卡只加熟练度不加成长值。
- **不做**：抽卡、开箱、概率掉落、付费复活、排行榜强制社交。这些会把学习工具变成赌博机制，明确排除。
- **离线**：已下载关卡可离线玩，进度本地落库，联网后同步。
- **中断恢复**：中途退出保留当前关卡进度与剩余生命值，24 小时内可续。

数据实体：

```swift
struct LevelDefinition: Codable, Identifiable {
    let id: String; var chapterID: String; var title: String
    var knowledgePoints: [String]; var questionIDs: [String]
    var starThresholds: StarThresholds; var order: Int
}
struct LevelProgress: Codable, Identifiable {
    let id: String; var levelID: String; var stars: Int
    var attempts: Int; var bestAccuracy: Double; var updatedAt: Date
    var bossDefeatedQuestionIDs: [String]
}
```

验收：任选一个章节，从地图进入 → 通关 → 星级正确 → 成长值增加 → 错题进 BOSS 关 → 连续答对 3 次后标记击败 → 薄弱点页面同步更新。

## 4. 数据联动矩阵

| 触发事件 | 写入 | 被动刷新 |
| --- | --- | --- |
| 完成一节课 | 课程进度、学习记录、成长值 | 首页任务、宠物动画、社区动态、统计 |
| 完成一组题 | 练习记录、正确率、薄弱点、成长值 | 首页任务、错题本、宠物动画 |
| 完成一次面试 | 面试记录、反馈、薄弱点、成长值 | 面试历史、推荐课程、宠物动画 |
| 每日打卡 | 连续天数、成长值 | 首页、社区状态 |
| 认领或换装 | 形象配置、拥有列表 | 成长页、社区场景 |
| 订阅或过期 | 权益 | 所有锁定内容、3D 会员装扮 |
| 注销账号 | 全量清理 | 登出并回到游客态 |

任一联动缺失即视为状态断裂，必须在阶段 7 修掉。

## 5. 样板验收标准

样板通过的标准是"能验收的完整产品"，不是"页面数量够多"：

1. 五条核心流程各自从头走到尾，中途不出现死页、失效按钮、空实现。
2. 每次数据变更后，切到任意相关页面看到的是一致结果（不刷新、不重启）。
3. 所有列表页具备加载/空/失败/离线四态；所有受限页具备无权限态。
4. 任一 AI、语音、支付、网络失败都有可恢复路径，不出现只有"重试"没有任何说明的死循环。
5. 3D 页面在真机（或明确标为未验证的模拟器）可渲染、可交互、可退出、可切后台恢复。
6. 会员与免费内容边界可验证：变成非会员后锁定内容立即回到锁定态。
7. 交付说明的"未验证项"完整、具体、可复现。

## 6. 竞品格局与差异化（调研于 2026-11）

数据口径说明（重要）：
- App Store 不公开下载量，任何"XX 万下载"只代表**某个第三方商店显示的该渠道安装数**，不等于全量用户。
- 厂商自我宣传的用户数（"XX 万考生在用"）属营销口径，未经第三方验证，引用时必须标注。
- 小红书站内笔记需登录，无法批量核验，本节的判断只基于公开可检索信息。

### 6.2 空白位

调研范围内**没有发现**同时具备以下组合的产品：

1. 垂直到具体专业（税务专硕）而不是"通用考研"或"通用口语"；
2. 面试间还原 5 位导师围坐与分工提问，而不是单一 AI 头像；
3. 3D 形象 + 电子宠物 + 3D 学习社区作为学习陪伴载体；
4. 刷题游戏化闯关与知识点拆解绑定。

因此产品的差异化不是"功能更多"，而是**场景真实度 + 陪伴感 + 垂直深度**三件事同时做到。

### 6.3 竞争风险（必须承认）

- 头部综合平台是千万级用户量级，单点功能无法撼动，只能靠垂直深度与体验差异切入小众人群。
- AI 面试能力本身不构成壁垒，模型可替换、追问逻辑易复制；壁垒在**题库与评分量表的审核质量**和**场景资产**。
- 游戏化容易做成"热闹但不提分"，必须用"薄弱点是否真的下降"来验收，而不是用停留时长。
