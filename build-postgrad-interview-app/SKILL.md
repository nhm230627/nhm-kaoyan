# 考研复试 APP 开发技能

把本技能当作一套**可执行的工程约束**，不是灵感清单。按顺序执行，每步产出可验证的文件或可运行的页面。

## 何时使用

满足任一条即加载本技能：

- 从零搭建或迭代一款考研复试 / 经管类复试备考 APP；
- 需要原生 iOS 实现，涉及 SwiftUI 页面、RealityKit 3D 场景；
- 需要打通「课程 / 题库 / AI 面试 / 会员 / 3D 形象 / 社区」的统一状态；
- 需要交付高完成度样板 APP、做内测修正或上线验收。

不要用它做：纯网页演示、纯 UI 稿、单页原型、求职撮合或分销类功能。

## 三条铁律（违反即返工）

1. **不虚构完成度。** 「代码已写」不等于「构建通过」，「界面能点」不等于「流程闭环」。未经真实执行的构建、渲染、支付、真机测试，一律在交付说明里标注「未验证」及原因。
2. **3D 不可推迟。** 3D 形象、电子宠物、3D 社区是核心产品模块，不是第四期可选项。任何阶段划分都不得把它们移出最终交付范围。
3. **状态单一来源。** 学习记录、成长值、权益、面试记录必须由同一数据层写入。禁止两个页面各自算一套成长值。

## 两条产品原则

1. **场景真实优先于界面好看。** 模拟面试必须还原真实考场：会议室、长桌、5 位导师围坐分工提问、考生第一人称视角、20 分钟节奏。不得用一个头像或一句提问代替导师席。真实流程与权重必须引用可核验来源（教育部规定、招生单位复试细则），并标注"训练量表，非院校官方评分"；不得把某一校的规则写成通用标准。
2. **游戏化服务于知识点掌握，不是给题库换皮。** 闯关的核心是知识点拆解、错误归因与记忆强化，画面保持轻量。禁止抽卡、开箱、概率掉落、付费复活这类赌博式机制。

## 执行前：确认运行环境边界

先探测并记录，写进交付说明的第一节：

| 检查项 | 命令 / 方式 | 决定什么 |
| --- | --- | --- |
| 主机平台 | `uname -s` / 系统信息 | Windows / Linux 无法编译 iOS，只能产出代码与工程结构 |
| Xcode 与 SDK | `xcodebuild -version`、`xcrun simctl list` | 能否构建、能否跑模拟器 |
| 真机 | `xcrun devicectl list devices` | 能否做 3D 渲染与性能实测 |
| 现有工程 | 读取目录、`Package.swift`、`.xcodeproj`、`git log` | 复用还是新建 |

若不在 macOS + Xcode 环境：**继续产出完整可编译的工程源码，但把构建、模拟器、真机、3D 帧率、支付回调全部标记为「未验证（缺 Xcode / 缺真机）」**，并在交付说明给出在 macOS 上的验证命令清单。不得用「应该能跑」代替结论。

## 工作流

### 第 0 步：现状盘点

1. 读取现有工程结构、依赖清单、设计资源、测试目录、提交历史。
2. 输出三张清单分开列：**已确认需求** / **技术假设** / **待确认事项**。
3. 标出可保留的模块。已能维护的代码不得无理由重写；重写必须写明理由（架构冲突、无法测试、不可扩展）。
4. 若目标目录为空，直接进入第 1 步，不要为「盘点」编造内容。

### 第 1 步：完整体验地图

在写任何界面代码前，先落一份地图（写入项目内 `docs/experience-map.md`，不属于本技能文件）：

1. 页面清单：页面名、所属模块、入口来源、返回路径、所需权限、所需权益。
2. 导航结构：Tab 与栈的层级，3D 场景页与普通页的跳转关系。
3. 核心流程五条，必须端到端可走通：

| 编号 | 流程 | 验收点 |
| --- | --- | --- |
| A | 注册 → 备考档案 → 学习计划 | 计划生成后首页出现今日任务入口 |
| B | 课程或刷题 → 学习结果 → 宠物成长 | 完成后成长值增量与结果页展示一致 |
| C | AI 面试 → 追问 → 反馈 → 错题或课程推荐 | 反馈中的薄弱点可跳转到对应题库/课程 |
| D | 认领 3D 形象 → 进入社区 → 伙伴互动 → 学习提醒 | 社区里看到同一形象与状态 |
| E | 会员内容 → 权益判断 → 购买或恢复购买 | 降级后会员内容立即回到锁定态 |
| F | 刷题闯关 → 通关星级 → 成长值与错题 BOSS | 星级判定正确，错题进 BOSS 关，薄弱点同步更新 |

4. 逐条检查：**不存在无行为的核心按钮**，**不存在跨页状态断裂**。发现即在实现前修地图。

详细页面字段、状态矩阵与验收标准见 `references/product-experience.md`，进入第 2 步前读一次，做验收时再读一次。

### 第 2 步：设计系统

1. 先调用当前环境可用的 iOS 界面设计规范（若存在相关技能/规范文件，读它；否则按 iOS Human Interface Guidelines 落地）。
2. 定义并落成代码常量：色彩（含深色模式双套）、字体层级、间距刻度、圆角、图标规格、组件清单。
3. 保证 2D 页面与 3D 场景的视觉连续：同一套色板、同一套文字层级、同一套按钮形态；3D 场景的 HUD 不得另起一套风格。
4. 覆盖动态字体、VoiceOver、对比度、44pt 触控区、减少动态效果。

组件命名、状态定义与可访问性细则见 `references/design-system.md`。新建任何界面前读它，新增组件时同步回写。

### 第 3 步：模块化架构

1. 按 UI / 领域 / 数据 / 网络 / 存储 / AI / 语音 / 会员 / 3D 切分模块，边界见 `references/architecture-data.md`。
2. 每个远端能力先定协议，再给 mock 实现，最后才是真实实现。**mock 与真实实现必须共用同一协议与同一异常语义**。
3. 建立统一数据源：用户、学习记录、成长值、权益、面试记录各只有一个写入者。
4. 密钥从环境变量或本地配置文件读取，并在 `.gitignore` 中排除。禁止写入源码、测试、示例、日志。
5. 禁止因为使用 mock 就跳过加载态、失败态、超时、重试与冲突处理。

### 第 4 步：分阶段实施

阶段表示开发顺序，**不表示后续模块可以从交付中删除**。每阶段结束跑一次构建与对应测试，再进入下一阶段。

| 阶段 | 范围 | 退出条件 |
| --- | --- | --- |
| 1 | 工程骨架、设计系统、导航、核心数据模型 | 空壳工程跑通 Tab 切换，设计常量可复用 |
| 2 | 学习首页、课程、资料、题库、学习记录 | 流程 A、B 的数据写入正确，四类页面状态齐全 |
| 3 | AI 面试、语音降级、反馈、复盘 | 流程 C 闭环，语音失败能落到文字模式 |
| 4 | 3D 形象、电子宠物、成长、动画 | 认领与个性化可保存，成长值与阶段 2 数据同源 |
| 5 | 3D 社区、学习伙伴、状态同步 | 流程 D 闭环，离线与重复事件不产生脏数据 |
| 6 | 会员、消息、个人中心、隐私设置 | 流程 E 闭环，降级/恢复购买状态正确 |
| 7 | 全链路联调、性能、测试、内测修正 | 门禁全绿或缺陷显式登记 |

阶段 3 的状态机、反馈结构与模型适配见 `references/ai-interview.md`。
阶段 4、5 的场景结构、资产规范、加载策略与轻量模式见 `references/3d-community.md`。开始这两个阶段前必须先读，不要凭直觉设计 3D 层。

### 第 5 步：验证

1. 每阶段结束执行：构建、单元测试、受影响模块的 UI 测试。
2. 3D 阶段额外执行：实际渲染、相机操作、热点点击、后台切换恢复、内存警告模拟。
3. 核心流程 A–E 各跑一次端到端。
4. 验证结论只写实际结果。失败就写失败、写错误信息、写复现步骤。
5. 环境不具备的能力（真机构建、支付沙箱、实时同步压测）单列「未验证」并给替代验证方案。

测试矩阵、性能检查项与上线验收表见 `references/quality-release.md`。进入阶段 7 前读它，交付前逐项勾。

## 质量门禁

每个阶段结束自查，任一不过不得宣称该阶段完成：

- [ ] 页面有加载、空白、失败、离线、无权限五种状态，且都有可见反馈。
- [ ] 新增数据字段只有一个写入者，其他模块只读。
- [ ] 成长值、权益、进度变更后，相关页面无需重启即刷新。
- [ ] 语音、AI、支付、网络失败路径各有一条可复现的降级方案。
- [ ] 未审核的 AI 生成题目不进入正式题库。
- [ ] 日志与埋点中无密钥、无个人信息、无转写原文与原始语音。
- [ ] 3D 页面有轻量模式入口，减少动态效果开启时自动生效。
- [ ] 本阶段所有「已完成」项都能指出对应的执行证据（构建日志、测试输出、截图或真机记录）。

## 禁止事项

- 不把样板缩减为静态 UI，不删减为「只有学习 + 面试」的简化版。
- 不删除或弱化 3D 形象、电子宠物、3D 社区。
- 不虚构院校政策、导师观点、真题、AI 能力、支付结果、3D 性能、测试结论、上架状态。
- 不把浏览器预览或 WebGL 效果当作 iOS 真机验证结果。
- 不将密钥、个人信息、原始语音写入日志、示例或仓库。
- 不创建空文件、占位文档、无用途脚本、README / CHANGELOG 之类无关文件。

## 交付时必须回答

1. 技能 / 工程目录与产物路径；
2. 完整文件清单（含每个文件的作用一句话）；
3. 已跑通的核心流程编号与对应证据；
4. 3D 能力覆盖到的具体项（认领、装扮、成长、动画、社区场景、社交、同步、轻量模式）；
5. 样板已实现的模拟能力 vs 仍需接入的正式服务的分界表；
6. 实际执行的验证项，以及未验证项及原因。
